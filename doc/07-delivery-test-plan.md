# 07 软件工程实施与测试计划

版本：1.0｜2026-10-09｜展示系统业务已实现；本文件保留原验收编号，实际验证记录见14。

## 1. 阶段与质量关卡

采用小步迭代的软件工程流程：先建立需求与设计基线，再分模块实现，每个增量包含测试和演示。下列工期为单开发者参考工作日，不是交付承诺；业务反馈、环境准备及依赖安装时间另计。

| 阶段 | 预计 | 主要任务 | 产物与退出条件 | 当前状态 |
| --- | --- | --- | --- | --- |
| P0 需求分析 | 1～2 天 | 整理 FR/NFR、默认假设、范围、验收场景 | 需求规格和追踪矩阵，业务核对 A01～A08 | 按用户确认的跨单、五级、单容器要求及已记录默认值实施 |
| P1 概要/详细设计 | 1～2 天 | 模块、ER、UML、算法、接口和页面 | 设计无关键矛盾；手算数量与状态流可复现 | 基线与最终实际设计均完成，见13 |
| P2 工程初始化 | 1 天 | 检查工具、创建.venv、锁依赖、开发库、应用骨架、账号与单容器 | 本机/容器均运行，迁移、健康及浏览器测试通过 | 完成，见10 |
| P3 主数据与销售 | 2～3 天 | Item/BOM、版本、无环校验、销售 CRUD | FR-01～07/12/13 对应用例通过 | 完成，见11及14 |
| P4 建议与发布 | 4～5 天 | 来源展开、跨单合并、五级排序、多对多分配、人工调整、幂等发布 | 合并及数量守恒正确；并发发布不超排 | 完成，实际候选聚合设计见13 |
| P5 生产与回传 | 3～4 天 | 生产CRUD、共享依赖、按等级回分、原回分冲销、取消影响、轮询 | 跨订单部分完工正确，回分与销售一致 | 完成，见12～14 |

## 2. 开发执行顺序

1. 核对默认假设，冻结第一版需求编号；记录改变后的影响，而不是边开发边猜规则。
2. 检查Python3.12、Node、PostgreSQL及Docker环境；开发先创建项目.venv，再安装后端依赖、初始化工程和开发库，生成首批迁移。前端依赖由Node工具链管理。
3. 先实现领域规则与服务，再接 API 和页面。优先完成 Item、BOM、Sales，保证计划输入可信。
4. 实现来源展开、兼容合并、五级排序及分配守恒，用同产品跨单、共享半成品、多父任务和深层图验证，再实现发布事务。
5. 完成生产CRUD、共享依赖、幂等报工、按等级回分、精确冲销及取消影响预览，再接销售聚合和自动刷新。
6. 每阶段先跑相关测试和检查；验收阶段完成集成、并发、端到端与演示，不在无变更时重复跑无关检查。
7. 实现[09单容器部署计划](09-development-deployment.md)，实测D01～D07（对应NFR-09）；提供启动、种子、持久化、备份恢复和验收记录，不把计划写成已通过。

## 4. 测试分层与数据集

- 单元测试：类型/无环、展开、跨单合并、五级拓扑排序、回分守恒与SALE进度。独立算法测试不依赖HTTP。
- PostgreSQL 集成测试：外键/部分唯一约束、事务锁、报工幂等、并发发布、回滚、历史保护。不得用 SQLite 的通过结果代替 PostgreSQL 并发验证。
- API 测试：CRUD、筛选、错误结构、revision、幂等键及状态机。
- 前端测试：必要的数量输入、表单类型限制、编辑冲突及刷新状态，不为静态文案编写镜像测试。
- 端到端测试：完整销售到生产闭环，以及销售/生产草稿 CRUD 两条短流程。

种子数据至少包含：三类物料；全原料 BOM；三级混合 BOM；同一半成品在多个路径复用；多个订单共用半成品；同优先级/空交期；独立生产单；待开工、生产中、暂停、完成等状态。负面数据通过测试构造，不写入正常演示库。

## 5. 演示脚本

1. 登录唯一用户，展示三种物料及各自溯源输入框。
2. 创建并删除一张销售草稿，再按 04 算例创建 SO-A、SO-B 并确认；展示原料不能被选择。
3. 展开 F→S→T→R3，展示生效 BOM 版本与层级。
4. 同时选择两单生成建议，核对T42/S14/F5三个合并任务及来源分配；显示最高来源等级，填写目标日期后发布。
5. 再次生成建议，观察相同需求没有重复任务。
6. 创建、编辑、查看、删除独立半成品生产草稿批次，展示生产单CRUD。
7. 完成T42，S先报12，查看A内部组件10/B销售2；A销售0%、B50%。再完成S剩余2并给F报2，A40%、B100%。
8. 在另一页签观察自动刷新；报完 F 剩余 3 后 SO-A 生产完成。
9. 查看BOM快照、溯源、报工和回分流水；合法冲销最新报告并恢复重报。
10. 用04的P/Q算例展示两单同成品合并P9、五级排序、P报6先满足A后部分满足B。
11. 新建未开工共享批次，预览取消会影响的全部销售单；确认取消生产后，其他销售单仍有效且恢复待排。

## 6. 风险与变更控制

| 风险 | 对策 |
| --- | --- |
| “不考虑产能”被误解成可直接跳过子件制造 | 界面显示依赖阻塞，需求明确区分依赖与产能 |
| 共享半成品造成漏算或重复计数 | 来源路径保留，任务合并；仅SALE回分计销售，检查数量守恒 |
| 取消共享任务伤及其他订单 | 显示完整关联组件与来源，确认后释放占用，不取消其他销售 |
| 无库存模型却允许取消已生产子件 | 已开工关联组件禁止取消，未来扩展库存后处理余量 |
| 低等级大数量搭载最高等级任务 | 明确整批继承最高等级及前置整单完成规则；后续按业务需要增加拆批 |
| 高频变更使候选方案过期 | 明示输入版本、保留旧方案，重新生成后人工复核 |
| 深层 DAG 展开爆炸 | 批量读取、迭代遍历、节点预算和明确失败 |
| 轮询达不到所需实时性 | 先验证 3 秒展示目标；若改变要求，更新 A03 与推送设计 |

每次变更记录：原因→FR/假设→数据/API/页面→测试→版本。本次v0.2已将跨单合并纳入首版，撤销A04原限制，新增FR-15/16和T28～T37；库存、在制追加、拆批、边产边装、损耗、工序/产能仍需另评估。
