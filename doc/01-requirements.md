# 01 需求规格说明书

版本：0.3｜2026-10-09｜跨订单合并、五级优先级、venv开发及本机单容器部署已明确。

## 1. 范围与术语

系统用于展示定制化排产流程：维护物料与 BOM，汇总多个销售订单的需求，跨订单合并兼容生产任务，按五级优先级生成建议，人工调整并发布，报工按来源回分并反馈到排产页面和各销售单。

一个登录用户操作全部页面。“销售端、生产安排端、产线端”指三个业务视图，不增加三个权限角色。不做注册、多租户、复杂权限、采购、仓储、财务、设备采集、工序路线、产能优化。

| 术语 | 定义 |
| --- | --- |
| 物料 Item | 成品、半成品、原料的统一主数据 |
| BOM | 制造指定数量父物料所需的直接组件及数量 |
| 需求分配 | 某销售行或某制造路径分配到生产任务的数量，区分 SALE、COMPONENT、STANDALONE |
| 合并生产单 | 相同物料与兼容制造版本的多来源需求共同生产，可同时供应多个订单/父任务 |
| 生产批次 | 一次候选方案发布或手工创建的任务集合，内部具有多对多供给依赖 |
| 建议批次 | 一次基于需求与 BOM 快照生成的可编辑方案 |
| 生产完成 | 销售行 SALE 分配累计合格量达到需求；共享生产单可尚未全部完成，不等同于已发货 |
| 溯源信息 | 每个 Item 可填写的文本，如来源、图号、供应商说明；不等同于完整批次谱系 |

## 2. 需求清单

原始描述中编号 6 重复，以下使用稳定的需求编号避免遗漏。

| 编号 | 功能要求 | 可验证结果 |
| --- | --- | --- |
| FR-01 | 物料 CRUD，类型限定成品、半成品、原料 | 三种类型可筛选、录入、查看、修改；已引用物料禁止删除 |
| FR-02 | BOM 不设固定层级，支持复用和展开 | 十层以上结构可保存、展开；无 level1/level2 等固定列 |
| FR-03 | 成品组件只允许半成品与原料，或全部原料 | 成品作为任何 BOM 子项时被拒绝 |
| FR-04 | 半成品组件只允许半成品与原料，或全部原料 | 半成品递归组合成功；直接或间接循环被拒绝 |
| FR-05 | 原料不能拆分 | 原料不可创建 BOM，不生成原料生产单 |
| FR-06 | 成品、半成品均可作为生产单最终产品 | 二者均可手工建单或从建议生成 |
| FR-07 | 销售单 CRUD，只允许成品、半成品 | 新增、查询、编辑、删除草稿成功；原料销售行被拒绝 |
| FR-08 | 跨订单合并生产，按简单五级优先级安排，不核算产能 | 同产品/兼容BOM合并，任务取最高来源等级并保留依赖和来源数量 |
| FR-09 | 人工修改最终生产安排 | 按来源销售行调整本次数量后重算合并；可改顺序、日期、产线及备注，再发布 |
| FR-10 | 生产单 CRUD 与生命周期管理 | 草稿可增删改查，已发布单按状态进行调整、取消、开工、暂停和报工 |
| FR-11 | 合并生产进度回分到各来源销售单 | 部分完工按冻结来源优先级依次分配；同一数量只记一次，组件用途不误计销售完成 |
| FR-12 | 三类物料各有溯源字段 | 创建和编辑各类物料时均可填写；发布时保留快照 |
| FR-13 | 单用户全权限展示系统 | 一个登录账号可完成所有演示操作，不要求角色分配 |
| FR-14 | 先文档后开发，包含 UML 与数据库关系图 | 需求、架构、设计、测试、实施和调研文档齐全 |
| FR-15 | 生产单和销售需求支持多对多数量关联 | 一个生产单满足多销售行，一个销售行可由多批次完成，保留来源计划量/完成量 |
| FR-16 | 共享任务修改/取消保护其他订单 | 显示完整影响范围，禁止按单一订单直接删除共享任务；未开工组件取消后释放各单占用 |

## 3. 业务规则

### 3.1 物料与 BOM

- `FINISHED` 可作为 BOM 父项和销售/生产最终产品，不能作为 BOM 子项。
- `SEMI` 可作为 BOM 父项、子项及销售/生产最终产品。
- `RAW` 只能作为组件或原料需求行，不能拥有 BOM、出现在销售明细中或作为生产产品。
- 同一物料可能被不同 BOM 多次引用；每个 BOM 内同一组件仅有一行，数量汇总填写。
- BOM 基准产量和组件用量必须大于 0；发布 BOM 至少一个组件，所有半成品组件必须有生效 BOM。
- BOM 可保存未完成草稿；发布和排产前校验完整性、循环及物料启用状态。自引用、跨多个半成品形成的环均禁止。
- 生效 BOM 版本冻结；修改通过复制新草稿并发布。新版本只影响后续建议；旧生产单按原快照执行。
- 物料有任何 BOM、销售、计划或生产引用后，其类型、计量单位不可直接更改；可修改名称、溯源说明，但历史快照保持原值。
- “无限层级”表示不设业务层数上限；采用迭代遍历、分层加载，避免 Python 调用栈限制。超出计算资源预算时返回明确错误，不静默截断结果。

### 3.2 销售与生产 CRUD

| 对象/状态 | 新增 | 查询 | 编辑 | 删除/取消 |
| --- | --- | --- | --- | --- |
| 销售草稿 | 支持多明细 | 支持列表/详情 | 全部业务字段 | 无引用时物理删除 |
| 已确认销售单 | — | 含分配量与生产进度 | 优先级、交期、备注可改；新增行或增加原产品数量；减少量不得低于有效 SALE 占用 | 有有效生产分配时拒绝直接取消；先预览并合法取消关联生产组件，再取消目标销售单 |
| 已完成/取消销售单 | — | 保留历史 | 备注 | 禁止硬删除 |
| 手工生产草稿 | 成品/半成品；多销售行来源或独立生产 | 支持 | 产品、来源分配量、日期、备注，重新展开并合并 | 整个草稿批次可删除 |
| 已发布且关联组件全部未开工 | — | 含多订单分配 | 顺序、日期、产线备注；数量变更取消组件后重新生成 | 预览全部受影响订单，再取消完整关联组件；不自动取消其他销售单 |
| 关联组件有任意开工记录 | — | 含报工、回分和依赖 | 调整未开工单顺序、日期；生产中可暂停/恢复 | 禁止取消、删除和变更数量，避免无库存模型下处理余量 |
| 已完成生产单 | — | 保留历史 | 备注 | 禁止删除 |

确认销售单尚无生产引用的行可更换产品；已有生产引用行保留历史，不可更换产品或删除重建。需要替代产品时新增行并按取消规则处理原需求。

未发布建议和生产草稿不占用销售量，只有已发布有效 SALE 分配占用；同一需求可有多个候选方案，发布时锁内防超排。销售数量、等级、交期或 BOM 变更使候选方案过期。手工生产绑定销售时产品须一致，独立生产不自动冲抵销售。已发布分配冻结等级及回分次序；修改销售等级不追溯转移完成量，具体见04。

### 3.3 排产与人工调整

优先级固定五级，1最高、2高、3普通（默认）、4低、5最低；同级按交期（空值最后）、创建时间、订单ID、明细行号、路径排序。各来源及组件继承订单等级；合并任务取最高来源等级，保留各来源分配。依赖优先于序号，先制造前置半成品。低等级数量可能随高等级合并批次提前生产。

不计算设备负荷、班次、工时或自动开始/完工时间。人工日期为目标日期，可重叠，不作为产能可行性承诺。

同产品/同兼容制造版本跨订单合并；共用半成品亦合并。用户按销售行降低本次安排量或排除需求，系统重算任务总量、分配、依赖与原料；不能直接改总量而不说明来源变化。发布完整重算后的候选方案，不能挑选孤立父/子任务。人工改顺序可覆盖等级建议但须记录原因，不得违反依赖。

### 3.4 报工与进度

- 正常报工是正数增量合格产量，累计不得超过计划数量；生产单开工后才可报工。
- 报工带唯一请求键，重复提交不得重复累计；错误报工通过有原因的冲销记录修正，不覆盖历史记录。
- 首版不处理不良品、返工、损耗或报废；界面字段标明“合格完成数量”。
- 所有前置生产单全部完成才允许父单开工；共享任务可以存在多个父单，此规则不核算产能。
- 报工按发布时冻结的来源等级/同级排序依次填满分配，写回分流水；每份合格量只能归属一个分配。
- 销售行进度 = SALE 分配累计完成量 / 销售数量；COMPONENT 只反映内部制造进度。多行显示已完成行数和逐行进度，不混加单位。
- 只可完整冲销本单最新未冲销的正数报告，反向恢复原回分；下游已开工时禁止冲销供给，禁止用当前等级重分历史产量。
- 自动刷新失败保留最后数据并显示时间与重试状态；不能把旧数据标成实时。

## 4. 非功能要求（待实现验证）

## 5. 完成定义

需求规则在文档、数据库、服务、API、页面和测试间可追踪；能够演示“多订单确认 → 跨单合并 → 五级排序 → 人工调整 → 发布 → 报工按来源回分 → 各订单进度”，以及销售/生产草稿 CRUD、共享半成品依赖和取消影响保护。演示数据、启动说明和限制随交付提供。
